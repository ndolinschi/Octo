## P0 — broken

### 1. "+" menu opened by the button cannot be used or dismissed from the keyboard
- Where: `components/chat/ComposerMenu.tsx:144-146` (focus effect) with `:177` (`if (!pos) return null`).
- Evidence (t11.js): after clicking or pressing Enter on "Insert a file, agent or action", `document.activeElement` stays the "+" button. Typing "glob" leaves the list unfiltered and the textarea empty; ArrowDown ×2 leaves the first option selected; Esc leaves the listbox open. Only an outside click or a second click on "+" closes it. The `/` and `@` routes work.
- Cause: the effect `if (props.query === null) search.current?.focus()` runs on the first commit, when the panel has not rendered yet because `pos` is still null; its dependency `[props.query]` never changes afterwards.
- Fix: focus when the panel exists — add `pos !== null` to the dependencies, or focus from a callback ref on the input.

## P1 — clearly wrong, visible to the owner

### 2. Status chips and "Jump to latest" have no focus ring
- Where: `components/chat/FloatingComposer.tsx:22` (`CHIP … shadow-float`), `components/chat/ConversationView.tsx:211` (`shadow-pop`), base ring in `styles.css:203-207`.
- Evidence (t24.js): chip focused with Shift+Tab, `:focus-visible` true, computed `box-shadow` = only the float shadow (`rgba(255,255,255,.08) 0 0 0 1px, rgba(0,0,0,.7) 0 8px 24px -8px`), outline transparent. Crop `chip-focus-zoom.png` shows no ring. The shadow utility overrides the base-layer ring.
- Fix: add `focus-visible:shadow-[0_0_0_2px_var(--octo-focus),var(--octo-shadow-float)]` to both, or move the global ring to `outline` so shadows can never cancel it.

### 3. Focus is dropped to `<body>` after the main file actions
- Evidence (t27.js, t9.js, t22.js, t20.js): keyboard Enter on "Show files" → `body` (contract: focuses the filter); Enter on a tree row that opens a file → `body` (neither editor nor row); chip click "Show the conversation" → `body` (contract: "focuses Chat"); picking a file in the overlay tree → `body`; creating a project → focus returns to the sidebar "New project" button instead of the composer.
- Where: `state/workspace/WorkspaceProvider.tsx` (`openTool`, `focusChat`), `components/files/FileView.tsx` (`openHere`, the Files tab turning into a File tab remounts the tree), `components/project/ProjectDialog.tsx`.
- Fix: after `openTool("files")` bump `focusTreeTick` also on first mount; after opening a file focus the editor (or keep the tree row focused); `focusChat` should focus the composer textarea; after create, focus the new project's composer.

### 4. Turn rail does not scale and its card is clipped
- Where: `components/chat/TurnRail.tsx:35` (`ul`, 8px per request, no max height / overflow) and `:81` (card), host in `components/chat/ConversationView.tsx` (`absolute top-2 right-full mr-1`).
- Evidence: Stress test (100 requests): rail = 16×800px at x 470–486, 4px from the text column — a full-height "zipper" beside the text (`rail-clicked-1440.png`, `stress-table-pinned2-light.png`). At a 700px-high window the rail is still 800px (t14.js): the newest ~30 markers, including the current one, are cut off under the composer (`stress-h700.png`). The hover card for the top markers sits at y=73 and is cut by the chat header (`rail-clicked-1440.png`, top left).
- Fix: cap the rail to the visible height (compress to `min(8px, available / n)` or window it around the request in view), keep 12–16px between rail and text, lighten inactive ticks (`line-strong`), clamp the card inside the scroll area (flip below / shift down).

### 5. Pinned long prompt can never be expanded
- Where: `components/chat/StickyPrompt.tsx:36-44` and `:64-80`.
- Evidence (t15.js): 61-line prompt pinned, span `scrollHeight 1430 > clientHeight 66`, yet the box renders as `<div aria-hidden>` — no "Expand the pinned request" button exists. Screenshot `stress-table-pinned-dark.png` (text ends "rows….").
- Cause: `setClamped(true)` swaps `div` → `button`, which remounts the span; the ResizeObserver still watches the detached span (0 > 1 is false) and flips `clamped` back.
- Fix: render one element type in both cases (always a `button`, `disabled`/`aria-hidden` when not clamped) or return early when `!el.isConnected`.

### 6. Code blocks are not syntax-highlighted (chat and Markdown preview) — owner's explicit note
- Where: `components/chat/Markdown.tsx:39-41` (`<pre><code>{code}</code></pre>`, one `text-fg` colour).
- Evidence: `demo-one-dark.png` (ts block in the chat), `md-preview-edited-1920.png` (preview).
- Fix: colour with the already-bundled Monaco (`monaco.editor.colorize(code, lang, {})` behind the existing lazy loader, plain text until it resolves) so chat and editor share one theme; no new dependency.

### 7. File-type icons are the weak glyphs
- Where: `components/files/fileIcons.ts`, `components/primitives/glyphs.ts`, used in tree, tabs, crumbs and the "+" menu.
- Evidence: DPR 4 crops `icons-tree-dark.png`, `icons-tabs-dark.png`: `FileCode` / `FileBraces` / `FileImage` at 14px with a 1.5px absolute stroke — the inner `<>`, `{}` and picture are 4–5px clots inside the page outline; three of five file glyphs are unreadable and differ only by that clot. This is the "busy file-with-badge" pattern Decision 14 itself rejects. Header tools: `Network` (Agents) is a dense 3-box diagram at 16px; `Settings2` (two sliders) for "Project settings" sits next to a gear "Settings" in the sidebar (two glyphs, one meaning family); `NotebookText` is the busiest of the three tools.
- Fix (lucide): files → plain `File` for everything, or badge-free glyphs `Braces` (config), `CodeXml` (code), `Image`, `AlignLeft`/`FileText` (text); drop the folder glyph or the chevron in tree rows (two glyphs per folder row; reference A shows only the folder). Tools → `Bot` or `Users` for Agents (keep `Bot` for a single agent → then `Workflow`/`GitFork` for the tree), `StickyNote` or `NotepadText` for Notes, `FolderTree`/`PanelRight` is already used for the tree toggle so keep `Folder`; Project settings → `Settings` (gear) or `SlidersHorizontal` everywhere, one of them. Consider stroke 1.25 at 14px.

### 8. Narrow file view: the overlay tree has no dismissal and covers the editor
- Where: `components/files/FileView.tsx:72-85,165`, `components/files/TreeColumn.tsx`.
- Evidence (t22.js, 1100px window): tree 280px over a 406px editor (69%); Esc with focus on the toggle or in the empty filter does nothing; clicking the editor does not close it (`overlay-tree-1100.png`). Only the toggle or picking a file closes it.
- Fix: in overlay mode close on Esc (when the filter is empty) and on outside pointerdown, return focus to the toggle; add a scrim-less shadow edge.

### 9. Breadcrumb with a long path degrades to "s. › s.. › c. ›" and a hard-cut file name
- Where: `components/files/FileView.tsx` (`Crumbs`).
- Evidence: `longname-dark.png`: folders shrink to one letter plus dots of different lengths; the file name is cut mid-glyph without an ellipsis and runs under the language-server spinner. The tab shows two ellipses ("ConversationT…Nav…": JS middle-shortening plus CSS truncation).
- Fix: collapse middle folders into one "…" crumb (menu on click), give the file crumb `min-w-0 truncate` with middle shortening, and let the tab use only one of the two shortenings.

### 10. Agents rows sit 4px under the tab pill; tab strip is 8 above / 0 below
- Where: `components/dock/TabStrip.tsx` (`px-pane pt-pane`, no bottom padding), `components/agents/AgentsPanel.tsx:107` (`pt-1`), `components/notes/NotesPanel.tsx`.
- Evidence (t16.js, t27.js): strip 9→45, tab pill 17→45, first agent row at 49. Two filled pills (active tab, selected "Orchestrator") nearly touch (`notes-solo-float-1440.png`). Chat and file views hide this because a 40px header row follows.
- Fix: give tool panels the same 8px inset as the strip's top (`pt-pane`) or a 40px header row like the other views.

### 11. Floating composer reserves no room in Agents / Notes
- Where: `components/dock/TabView.tsx:27-33`; panels keep `pb-4` (`AgentsPanel.tsx:107`, `NotesPanel.tsx:25`).
- Evidence: composer block is 72px + 16px inset = 88px, the lists end with 16px padding and cannot scroll further (t28.js: scrollHeight = clientHeight). With enough rows the last 2–3 are permanently under the composer. Not reproduced with demo data (4 agents, 0 notes) — confirmed from geometry and code.
- Fix: pass `onHeight` like the file view does and set the list's bottom padding to `height + 16`.

### 12. Content is sliced under the pinned prompt
- Where: `components/chat/StickyPrompt.tsx:83` (24px fade, opaque for 25%).
- Evidence: `stress-table-pinned2-light.png`, `demo-one-dark.png`: a table row's text is cut through the middle of its glyphs right below the box, with cell borders still visible.
- Fix: 8px opaque band + 32px eased fade (reuse the multi-stop easing of the glow), or snap the release point to block boundaries.

## P2 — polish

24. **Long rail jumps animate for > 1s** over 20,000px (t13.js; instant under reduced motion). Jump instantly beyond ~2 viewports.
25. **Bottom pin lost after the side group widens** (`longname-dark.png`: conversation left at request 97–100 with "Jump to latest" after opening a file).
26. **Chat header at ~370px**: both crumbs truncate to "Orbit mo… / Upgrade us …" with an uneven gap before "/" (`w-file-1100-dark.png`). Drop the project crumb first.

But at 960×560 and 14% it reads as a dim vignette, not a cue; it neither cheapens nor helps. Tighter and anchored to the composer (≈ 640×240, centre on the input's lower edge) or remove.
30. **Wording**: agent header "working" (lowercase) vs "Working…" elsewhere; composer footer shows a bare folder label ("orbit-app") with no icon or meaning.

## Not checked

## Verdict
Not yet "premium". The foundation is good — surfaces, type, spacing discipline, light theme and contrast are consistent and calm, and the file view matches the reference structure. What still breaks the impression: one broken entry point (1), invisible or lost keyboard focus (2, 3), the rail as a full-height zipper (4), unhighlighted code (6), clotted file glyphs (7), and the unfinished edges of narrow and long-content states (5, 8, 9, 12). None is large; 1–7 are each under an hour of work and would change how the product reads.
