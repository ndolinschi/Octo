## Verdict

1. **Solid engineering, not yet the product the owner asked to see.** Nothing is broken: 96 screen states with 0 horizontal scroll and 0 console errors, spacing audit total=0, tabs / composer / file view / palette all work, the composer race is really fixed.
2. **Decision 23 is built to the letter but only half in spirit:** sidebar, header, tab, team strip and Home all say "orchestrator", yet an idle project is still a chat transcript with a "Send follow-up" box, and the team is visible only while a turn runs.
3. **The two owner complaints stand:** the streak is now loud but still does not look like the reference (flat orange slab with a staircase edge, no hot core), and the right panel is still button-heavy (Usage opens with three segmented controls, one of them truncated to "3… 9…").

Counts: **Blocker 0 · Major 6 · Minor 13.**

### Blocker

### Major

**M1. Streak: bold now, but it reads as a flat poster stripe, not light (Decisions 21/21b).** Home, empty project, hero; 1440; both themes.
- Observed: the core is one saturated flat orange (#f4733c-like) slab about 18% of the short side with no luminance peak; the "near-white highlight on the core's upper edge" is not perceivable. Where the strength clamps to its top level there is no dither, so the orange/pink boundary is a hard pixel staircase (`streak-empty-core-zoom4x.png`). The grain exists only at the band edges; the "sparse noise over the whole background" is barely visible. The reference (`_refs.png`, `_ref-core-zoom2x.png`) is the opposite: a thin, white-hot core, warm on one side and blue on the other, long dark falloff, fine 1–2px grain across the whole surface.
- Hero: the title sits in a dark smudge punched out of the band (the scrim is visible as a blob, `hero-dark-1440.png`). Home: the project list and four cards cover roughly 60% of the panel, so the band shows only in gutters and corners (`home-dark-1440.png`). Empty project: no hard cut any more, but the 112px wash reads as a dark haze band over the brightest part (`streak-empty-top-edge-zoom3x.png`). Light theme is pleasant but pastel (`empty-project-light-1440.png`).
- Evidence: `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/streak-empty-core-zoom4x.png`, `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/_ref-core-zoom2x.png`, `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/hero-dark-1440.png`.
- Fix: make the core thin (3–5% of the short side) and bright (near-white centre → amber → red), keep the wide halo dark-blue and low; dither the whole ramp including the top level (never clamp to a flat fill); finer grain (2px) plus real full-surface noise at 8–12%; route the band so it passes beside the title instead of scrimming it; on Home let the band cross a free region (narrower card block or band above the list).

**M2. Usage: the range control is truncated at the default width.** Usage tab, 1440 (side group 366px) and 390, both themes.
- Observed: Range radiogroup is 112px; each radio 35px wide but its label needs 38 → "7d  3…  9…". Root cause: `Segmented` gives every segment `min-w-0 flex-1 truncate px-2` inside an `auto` grid column.
- Evidence: `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/usage-range-clipped-dark-1440.png`, `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/usage-dark-1440.png`.
- Fix: no `truncate` on 24px segments (`whitespace-nowrap`, `px-1.5`) or a fixed min width of 40px per segment.

**M3. Right panel is control-heavy ("garish buttons").** Usage / Details / Files side group, 1440, both themes.
- Observed: Usage starts with three bordered segmented controls in two sizes (28px Tokens|Cost|Limits, then 24px range and 24px scope) = 8 buttons and three filled pills before the first number; above them the strip carries up to 6 tool icons with two filled "on" states at once (Files + Usage) and a gear behind a divider. The editor's comment "+" and the send button are solid white squares on a near-black panel — the brightest things on screen.
- Evidence: `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/right-sidebar-sheet.png`, `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/file-comment-added-dark-1440.png`.
- Fix: one control style per panel — Tokens/Cost/Limits as plain text tabs with an underline; range and scope as two quiet text menus ("30 days ▾", "This project ▾") on one line; tool icons without fill for "open", only the active tab is filled; comment "+" in `fg-2` on `hover` fill, not white.

**M4. Decision 23 — letter yes, spirit partly.** Orchestrator tab, all viewports.
- Built as written (measured): sidebar = 7 project rows, 40px, 13/20 + 12/16, no nesting, no chevrons; header = name · state · agent stack · model · tokens; tab "Orchestrator"; team strip chips 24px collapsing to "2 agents working" at 390; Home = projects + "Orchestrators at work"; empty project copy and three facts; wording scan clean (no session/thread/chat/conversation).
- What still says "chat": (a) an idle project is a prompt bubble, a reply and a composer whose placeholder is "Send follow-up" — nothing shows what the orchestrator has (agents it ran, notes, plan) unless a tool tab is opened (`orch-idle-dark-1440.png`); (b) the team strip and header stack exist only while sub-agents run; (c) a team-chip click opens the agent run as a tab in the orchestrator's own group and covers the orchestrator (`agent-tab-dark-1440.png`); (d) the turn rail is hidden under 3 requests (`RAIL_MIN_REQUESTS = 3`, not in the decision), so Atlas and Orbit have no request indicator at all; (e) the sidebar "Working" mark is a static 6px dot, smaller and quieter than the "new activity" dot, so a working project is the least visible state; (f) no demo project shows "Needs you".
- Evidence: `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/orch-idle-dark-1440.png`, `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/orch-running-dark-1440.png`, `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/agent-tab-dark-1440.png`.
- Fix: keep a persistent one-line "team" row above the composer when idle (last run: "6 runs · 1 failed · 3 notes", opens Agents); placeholder "Give the orchestrator a task"; open agent runs in the side group by default; show the rail from 2 requests; animate the working dot (pulse or spinner, off under reduced motion) and make it at least as strong as the unseen dot; add a failed-turn project to the demo.

**M5. Focus still drops to `<body>` in five paths** (spec v6.2: "focus never on body"). 1440, dark.
- Observed (`document.activeElement` = BODY): header button "Show project details" (the tool buttons re-mount in the new group's strip); Ctrl+W on a tool tab; click on a tab's close button; "Split right" from the tab menu; Enter on a Home project row (should land in the composer).
- Evidence: logs of `i2.js`, `dx.js`, `f1.js` (NOTES-raw.md); `/tmp/claude-0/-home-user-Octo/7c5bf6ed-bfbb-5e95-9ca2-f0157268907d/scratchpad/review62/shots-final/three-groups-light-1440.png`.
- Fix: after any layout change call the existing `focusSoon(onlyIfLost)` with the new active tab (or its panel) as target; Home row → composer.

**M6. Streak draw time misses its target everywhere.** Home / empty / hero.
- Observed (`data-draw-ms`, 12 warm redraws each): Home 1440 dark median 6.1 ms (min 4.7), light 9.5; empty project 8.8; hero 8.4; Home 1920 median 20.5 ms (max 107). Target ≤ 4 ms. Cold first draw 8–24 ms. One draw per resize step, so a window drag redraws every frame. Also `streakCell(hostWidth)`: at a 1920 window the host is 1668px, so cells stay 3px (decision: 4px at ≥ 1920).
- Fix: cache the rendered ImageData per (cols, rows, theme) and during a resize scale the old canvas, redrawing once 100 ms after the last resize; or move the pixel loop to an OffscreenCanvas worker; pass the window width to `streakCell`.

## Other checks

- **Layout:** 16 screens × 3 viewports × 2 themes: no page-level horizontal scroll, no text outside the viewport, no un-ellipsised clipping detected by script; the two clipped items above were found by eye.
- **Interaction:** open / close / move / split tabs work and persist across reload (incl. active tab, three groups). Send → Stop → "Turn stopped" works; Enter while running gives the status line. Comment via Ctrl+Alt+C / Ctrl+Enter works; "+" lane at x 914–932, numbers from 933. Palette ↑/↓, "integr" → Open integrations. Menus: arrows, End, Esc returns focus.
- **Keyboard:** focus ring is a 2px box-shadow (white 60% dark, black 55% light) on every stop sampled; tab order is sidebar (14 stops) → tab → tools → header → transcript → composer; Ctrl+L jumps to the composer.
- **Reduced motion:** drift and spinner off; verified with `document.getAnimations()`.
- **Performance:** long transcript (21,739px, 2,822 nodes) scroll: median 16.8 ms, p95 25.3, 12 of 533 frames > 33 ms. Console: 0 errors, 0 warnings in every run.
- **Code:** the composer is one element across loading → empty → transcript (same position in one tree); verified live — same `<textarea>` node, focus and draft kept after creating a project and sending. Streak, TeamStrip, useUsage effects all clean up (RAF, ResizeObserver, interval, cancelled flags).
