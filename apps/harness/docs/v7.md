# v7: changes per turn, approvals, message queue, forms and secrets

Contract: [`docs/superpowers/specs/2026-11-10-v7-changes-queue-approvals.md`](../../../docs/superpowers/specs/2026-11-10-v7-changes-queue-approvals.md) and decision 43 of [`2026-11-10-project-harness-ui.md`](../../../docs/superpowers/specs/2026-11-10-project-harness-ui.md). This page is what the harness does, with the exact API. Client types: `@octo/agent-client` (`types.ts`; the v7 `Bridge` members are optional, HTTP bridge only).

## 1. Changes and diffs

Code: `internal/changes` (tracker, snapshots), `internal/diff` (line counts), `internal/projectstore/changes.go`, `internal/project/changes.go`, `internal/bridge/changes.go`.

**What is recorded.** Every change to a project folder an agent makes, as a row of `changes` (`turn_id` is the id of the user message that started the turn, `agent_id`, `folder`, `path`, `kind`, before/after hash, `added`/`removed`, `note`, `source`):

| `source` | Made by | How it is seen |
| --- | --- | --- |
| `write_file` | the built-in `write_file` tool | exact: content read before and after |
| `acp_fs` | an ACP agent's `fs/write_text_file` | exact |
| `bash` | one built-in `bash` call | before/after snapshot of the project folders |
| `acp_turn` | an ACP agent's own tools (an ACP sub-agent's run, or an ACP orchestrator's turn) | one snapshot window over the whole run; what `fs/*` already recorded is not counted twice |

`kind` is `created`, `modified` or `deleted` (the spec said "no delete tool"; bash can delete). Each recorded change also publishes `change.recorded` and `file.changed` (`source: "agent"`).

**Snapshots.** Per project folder the tracker keeps an index of every file (size, mtime, sha256) and, for text files, a copy in `{data-dir}/projects/{pid}/shadow/` (the pre-image). A window's "before" walk only refreshes the index; its "after" walk compares size/mtime, reads and hashes only files that differ, and records created/modified/deleted. Limits (fixed):

| Limit | Value | Beyond it |
| --- | --- | --- |
| files per folder walk | 20 000 | the walk stops (alphabetical for git folders), changes among the files not visited are not detected; a warning is logged |
| pre-image copy per file | 1 MiB | a later change is recorded without diff (`note: "too_large"`) |
| pre-image store per project | 256 MiB (unused copies are dropped first) | later changes of files that did not fit have `note: "no_preimage"` |
| file read to be hashed | 64 MiB | no hash: the change is recorded, no diff (`too_large`) |
| diff blob (database) | 2 MiB, text only | `binary` / `too_large`: the change is listed without diff |

Ignored paths: in a git work tree the file list is `git ls-files --cached --others --exclude-standard` (so `.gitignore`, `.git/info/exclude` and the global excludes apply and `.git` is never walked). Elsewhere `.git`, `node_modules`, `target`, `__pycache__`, `.venv`, `venv`, `.cache` are skipped. Symlinks are not followed. The first window of a harness run builds the baseline (one pass over the folders, bounded as above); the pre-image store starts empty at every harness start.

**Known limits.** Overlapping windows (parallel sub-agents) share one index: a change is recorded once, by the window that ends first, so it can be attributed to a sibling; a "before" walk is skipped while another window is open so it cannot absorb its changes silently. Edits a user makes while an agent's window is open are attributed to the agent. Files an agent writes with a secret in them are the user's files: the secret is in the diff blob.

**Retention.** After each turn and at start-up, blobs of changes older than 30 days are deleted (the row stays; `diff_available: false`, `note: "pruned"`); blobs no change refers to go too.

| Method | Path | Response |
| --- | --- | --- |
| GET | `/v1/projects/{pid}/changes?turn=` | `{ "turns": TurnChanges[] }`, newest first; one entry per file per turn (first before to last after, with `change_ids`, `agent_ids`); a file created and deleted again, or changed back, is left out |
| GET | `/v1/projects/{pid}/changes/{cid}` | `ChangeDetail`: the change plus `before`, `after` (null when not kept) and `diff_available` |
| POST | `/v1/projects/{pid}/changes/{cid}/revert` | `FileStat` (+ `deleted: true` for a created file that was removed). `409 file_changed` when the file no longer equals the change's after (for a deleted file: when it exists again); `409 revert_unavailable` when the content before was not kept |

Event `change.recorded` `{ seq, turn_id, change: FileChange }`. Older projects open unchanged; turns before the upgrade have no changes.

## 2. Approvals

Code: `internal/approval`, `internal/orchestrator/approvals.go`, `internal/permission` (the seam: `Request` gained `AgentID`, `TurnID`, `Policy`; the orchestrator's `approvalPolicy` answers ACP permission requests).

`access` is a project field (`PATCH /v1/projects/{pid}`, also on create): `supervised`, `accept_edits`, or `full`. Existing projects are `full` (migration default); **projects created without `access` get the server default**: `harness serve` uses **`supervised`** (unless `HARNESS_DEFAULT_ACCESS` overrides it). Code that embeds the service without a default (tests) gets `full`. A change of `access` applies to the next request, also inside a running turn; pending approvals stay pending.

In a `supervised` project these ask: built-in `write_file`/`edit` and `bash` (also for a sub-agent at any depth), ACP `session/request_permission` (kinds `read` and `search` are answered automatically), ACP `fs/write_text_file`. Under `accept_edits`, file edits/writes/deletes/moves are auto-approved while shell commands, network fetches, and other ACP actions still ask. Reads never ask. A request blocks only the agent that raised it. An ACP edit the user allowed through `request_permission` also covers the `fs/write_text_file` that carries it out (matched by the announced path, else one path-less edit), so one edit is one card. Permission requests that name only a tool call id are completed from the `tool_call` the agent announced (title, kind, locations, raw input).

Card: `Approval { id, agent_id, agent_label (role, or the plugin id), turn_id, kind: "write"|"command"|"acp"|"memory", title, detail { folder?, path?, diff? {added, removed}, command?, options?, memory_command?, memory_kind?, memory_text?, memory_about?, memory_path? }, created_at }`.

| Method | Path | Body → response |
| --- | --- | --- |
| GET | `/v1/projects/{pid}/approvals` | `{ "approvals": Approval[] }` pending only, oldest first |
| POST | `/v1/projects/{pid}/approvals/{id}` | `{ decision: "allow"|"allow_for_turn"|"deny", option_id?, note? }` → `204`; `404` when it is no longer pending; `400` for another decision |

`allow_for_turn` is remembered for (turn, agent, kind) and, for commands, the program (first word); for ACP the tool kind. Deny returns a tool error `Denied by the user[: note]` to a built-in agent, a JSON-RPC error to `fs/write_text_file`, and a reject option to an ACP permission request. ACP option mapping: allow → `option_id` if it is an allow option, else the first `allow_once`, else `allow_always`; deny → `option_id` if it is a reject option, else first `reject_once`, `reject_always`; none offered: the request is cancelled. `allow_for_turn` picks `allow_once`.

Cancelling the turn denies what is pending (`approval.resolved` with `deny`). **Unattended rule** (the spec is silent): a request nobody answers is denied after `HARNESS_APPROVAL_TIMEOUT` (a Go duration, default 30m; `0` or negative waits for ever). Pending approvals survive a UI reload, not a harness restart.

Events: `approval.requested { approval }`, `approval.resolved { id, decision }`, `project.attention { needs_you, approvals, inputs }` (whenever a count changes). Project JSON and summaries carry `needs_you`, `pending_approvals`, `pending_inputs` (`status` stays `idle`/`running`: a turn that waits is running).

## 3. Message queue

Code: `internal/orchestrator/queue.go`, `internal/projectstore/queue.go`.

`POST /v1/projects/{pid}/messages` → `202 { message }` when a turn started, `202 { queued: QueuedMessage }` when one is running (or messages wait ahead of it and the queue is not paused). At most 20 queued (`409 queue_full`). FIFO, persisted in `project.sqlite`. When a turn ends: completed → the next message starts; failed or cancelled (user cancel, shutdown) → a non-empty queue **pauses**. After a crash, recovery pauses a non-empty queue. A message sent while no turn runs always starts a turn, even with a paused queue. `turn.finished` is published after the turn's slot is released, so a client reacting to it never meets `turn_in_progress`.

| Method | Path | Body → response |
| --- | --- | --- |
| GET | `/v1/projects/{pid}/queue` | `{ paused, messages: QueuedMessage[] }` |
| PATCH | `/v1/projects/{pid}/queue/{qid}` | `{ text }` → `QueuedMessage` |
| DELETE | `/v1/projects/{pid}/queue/{qid}` | `204` |
| DELETE | `/v1/projects/{pid}/queue` | `204`, clears it (added: the UI's "Clear") |
| POST | `/v1/projects/{pid}/queue/resume` | `202` |
| POST | `/v1/projects/{pid}/queue/{qid}/send-now` | `202`; cancels the running turn (without pausing), then runs this message first |

Event `queue.updated { paused, messages }` after every change. `/cancel` stops the turn and pauses the queue; it never drops messages.

## 4. Forms and secrets (decision 43)

Code: `internal/inputs`, `internal/secrets`, `internal/orchestrator/secrets.go`.

**Tool `request_input`** (built-in agents at every depth, and the MCP tool list of an ACP orchestrator, which shares the same definition): `{ title, reason?, schema? , fields? }`, exactly one of `schema` and `fields` (both or neither: tool error "Pass fields or schema, not both"). It blocks the calling agent until the form is submitted or skipped; cancelling the turn closes it. Result text (JSON): `{"status":"submitted","values":{non-secret, typed},"secrets":{"password":"provided"},"use_as":{"password":"secret:password"}}`, or `{"status":"skipped"}`. A secret's id is its secret name (`NamePattern`: letter first, letters digits `_ . -`, at most 64).

- **`fields`** (legacy): `[{ id, label, kind: secret|text|select|confirm|path, options?, required?, help? }]`, 1 to 8 fields, a select needs 1 to 24 options. The harness converts them to a schema (`inputs.FromFields`): text → string; secret → string + `format: "password"`; select → string + `enum`; confirm → boolean (required → `x-octo.accept: true`, must be ticked); path → string + `x-octo.widget: "path"`; label → `title`; help → `description`.
- **`schema`** (spec `2026-11-15-dynamic-forms-mentions-design.md`, Part A; code `internal/inputs/schema*.go`): the MCP elicitation schema plus `x-octo`. `{type: "object", properties, required?, x-octo?: {order?, groups?: [{title, fields}], submit_label?}}`; a property is a string (`format` email | uri | date | date-time | password, `minLength`, `maxLength`, `pattern`), a one-of string (`enum` [+ `enumNames`] or `oneOf: [{const, title}]`), a `number` / `integer` (`minimum`, `maximum`), a `boolean`, or a many-of `array` (`items: {type: "string", enum, enumNames?}` or `{anyOf: [{const, title}]}`, `minItems`, `maxItems`); each with `title`, `description`, `default` and `x-octo: {placeholder, visible_when: {field, equals}, multiline, step, widget: "path", path_kind: file|folder, accept}`. A schema sent as a JSON string is accepted too.
  - **Limits** (refused, the tool error names the limit): schema ≤ 32 KiB, nesting ≤ 6 levels, 1–20 properties, ≤ 50 choices, ≤ 8 groups, property and group title ≤ 120 characters, description ≤ 500, placeholder ≤ 120, choice value and title ≤ 200, submit label ≤ 40, pattern ≤ 256 bytes and must compile in Go `regexp` (RE2; unanchored).
  - **Keywords.** Annotations `$schema`, `$id`, `$comment`, `title`, `description`, `additionalProperties` (top) and `$comment`, `examples`, `uniqueItems` (property) are accepted and dropped. Every other keyword is refused naming it (`$ref`, `$defs`, `allOf`, `if`, `exclusiveMinimum`, an unknown `x-octo` key, …); `type: "object"` properties and arrays of objects are refused; a keyword that does not apply to the field's kind (`minimum` on a string, `format` with `enum`) is refused.
  - **Rules.** Ids as `fieldID` (letter first, `[A-Za-z0-9_.-]`, ≤ 64); a password id must be a secret name and a password has no default; `visible_when.field` must be an earlier property, not a password and not an array, and `equals` (a value or a list of 1–50 values) must be values that field can have; a `default` must pass the field's own check; `password` only from `request_input` (`inputs.OriginTool`).
  - **Normalised.** `x-octo.order` always lists every property (the given order first, then the rest in document order); `properties` keep document order on the wire.

Every open form (`InputRequest`) carries `schema` (given or converted), `fields` (the legacy list; `[]` for a schema form) and `source: {kind: "tool"}`.

**Answer check** (`inputs.CheckAnswer`, one rule set for both shapes). A string that is absent or blank, an empty array and an absent number or boolean count as not answered: refused only when the field is in `required` (or a boolean has `accept`), otherwise dropped. A field hidden by `visible_when` is not required and is refused if sent. Unknown ids and wrong types are refused. Formats: `email` one `@`, no white space, a non-empty local part, a domain with a dot, not starting or ending with one and no empty label; `uri` a scheme (`[A-Za-z][A-Za-z0-9+.-]*:`), no white space, something after the colon, and a non-empty host after `//`; `date` RFC 3339 full-date; `date-time` RFC 3339 with seconds and an offset (`Z` or `±hh:mm`). Strings ≤ 16 KiB, lengths in characters; a password is at least 4 bytes as every secret. Values reach the model typed: strings, numbers (integers as whole numbers), booleans, lists of strings.

| Method | Path | Body → response |
| --- | --- | --- |
| GET | `/v1/projects/{pid}/inputs` | `{ "inputs": InputRequest[] }` open forms |
| POST | `/v1/projects/{pid}/inputs/{id}` | `{ skip: true }` or `{ values: { id: string | number | boolean | string[] } }` → `204`; `400 invalid_request` with `error.fields: { id: message }` (messages in the card's words: "Required", "Choose one", "Confirm to continue", "Enter an email address like name@example.com", "Enter a web address starting with https://", "Use 8 characters or more", "Enter a number from 1 to 10", "Enter a whole number", "Choose at least 1", "Doesn't match the expected format", "Not a field of this form", "This field is not shown, so leave it empty", …), `message` "One answer in the form needs attention." / "Some answers in the form need attention.", `details` "id: message; …"; never a value (an unknown key that is not id-shaped is named `(unknown)`); `404` |
| GET | `/v1/projects/{pid}/secrets` | `{ "secrets": [{ name, updated_at }] }` |
| PUT | `/v1/projects/{pid}/secrets/{name}` | `{ value }` → `204` (value 4 bytes to 16 KiB; `400` otherwise) |
| DELETE | `/v1/projects/{pid}/secrets/{name}` | `204`, `404` |

Events: `input.requested { input }` (the form, no values), `input.resolved { id, status: submitted|skipped|cancelled, provided: [secret ids], values: {non-secret values, typed} }`, `secrets.changed { names }`.

Mock model: `[form]` opens the legacy Credentials form, `[schemaform]` the "Sign in to staging" schema form (email, password, remember); both then report the tool result.

**Store.** `{data-dir}/projects/{pid}/secrets.json`, mode 0600, replaced atomically (temp file, fsync, rename, directory sync); never in SQLite. Values below 4 bytes are refused rather than stored: redaction of shorter strings would mangle ordinary text.

**Use.** A secret reaches a child process only through an explicit mapping, resolved by the harness when it builds the environment (after the child-env allow-list, so it wins):
- `bash` takes `env: { "NAME": "secret:<name>" }` (only `secret:` references are accepted; literal values are refused). The stored tool input holds the reference.
- `spawn_agent` (with `agent`) takes the same `env` for the external agent's process.
- Not supported: an ACP orchestrator's own process (it can delegate with `env`); outgoing headers of remote tool servers (the manifest has no header settings, the registry is shared).

**Never in** transcripts, events, logs, errors, usage rows, model context: every stored message passes a redactor (exact value and its JSON-escaped form become `[secret]`); `bash` output is redacted before it is returned; ACP text deltas are redacted across chunk boundaries; agent results, errors and the agents' stderr lines are redacted; validation and resolution errors name fields and secrets, never values. Tests scan transcripts, events, the log, usage, context and every GET after full turns (`bridge/v7_forms_test.go`, `bridge/v7_schema_forms_test.go`, `scripts/e2e-v7.sh`). Not covered: a value the agent re-encodes (base64, split over two lines), and files the agent writes (they are the user's files and are diffed like any other).
