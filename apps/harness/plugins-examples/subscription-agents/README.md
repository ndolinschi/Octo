# subscription-agents

Claude Code, GitHub Copilot, Grok, Codex, Cursor, OpenCode, Antigravity, Devin, Factory Droid, Oh My Pi and Pi as ACP sub-agents. Each runs on the subscription its own CLI is logged in to; the harness never reads the CLIs' credential files.

This plugin is **built into the harness binary** (`embed.go` embeds `plugin.json`; there is no copy), so plain `harness serve` has it, no key needed:

```bash
go run ./cmd/harness serve
curl localhost:8790/v1/plugins    # builtin: true; available, logged_in (null without a probe), models, hint
```

To change it, copy this directory into `{data-dir}/plugins/` (or pass it with `--plugins-dir`): a plugin of the same name replaces the built-in one. `--no-builtin-plugins` / `HARNESS_NO_BUILTIN_PLUGINS=1` turns it off.

**Only the scripted fake agent has been run against this harness.** Copilot, Grok and Codex follow vendor docs; the other entries come from vendor docs, the ACP registry and secondary sources and are unverified (binary names, flags, probe exit codes, auth method ids).

The harness passes these processes only an allow-list of its environment (see "Child environment" in the harness `README.md`; `HARNESS_CHILD_ENV_ALLOW` adds names) and always hides its own `ANTHROPIC_*`, `OPENAI_*`, `XAI_*`, `GEMINI_*` ... variables so a subscription is not pushed onto per-token billing; an entry's `env` (for example `"XAI_API_KEY": "${XAI_API_KEY}"`) passes a variable on purpose. The commands, logins and env vars per agent are tabulated in the harness `README.md`, "Running on subscriptions" (with the scrub rules); `auth.methods` / `auth.skip` and the `{modelArgs}` placeholder are described in `../README.md`.

**`flatRate` per entry** (used by automatic routing, `tier: auto`): `true` for claude-code, codex, copilot, cursor, antigravity and devin (the CLI's own subscription or plan is what is used; a key such as `CURSOR_API_KEY`, `WINDSURF_API_KEY` or `COPILOT_GITHUB_TOKEN` only authenticates that plan); `true` for grok too, **unless `XAI_API_KEY` is forwarded to it** (manifest `billingEnv`: variables that, when set in the environment the agent is started with, switch a flat-rate agent to per-token billing; decided at spawn, so a key from a spawn-time `env` counts; claude-code lists `ANTHROPIC_API_KEY` the same way, for a copied entry that forwards it); `false` for droid (token-metered plan with `FACTORY_API_KEY`), and opencode, omp and pi (they front arbitrary model providers whose billing is unknown). The choice is a judgement, not data: override it by copying the plugin (see above) and editing `flatRate`. **`strengths` per entry** (the owner's default, so a hard task can go to a subscription instead of always to the paid deep tier; copy the plugin and edit `strengths` to change it): `easy`, `medium`, `hard` for claude-code and codex; `easy`, `medium` for copilot and cursor; unset (never chosen by difficulty) for the rest.

**`requires` per entry** (commands that must be on PATH besides the entry's own command, else the agent is `available: false` with an `unavailable_reason` in `GET /v1/plugins`): only `pi` requires `pi` (its hint says "Needs pi on PATH" and its command is `npx`, which is there either way). Left out on purpose: claude-code and codex run through `npx` adapters and their hints say "log in with the CLI", not "install"; the adapters are said to bundle what they drive, and their login probe already reports a missing CLI as not logged in. Add `"requires": ["claude"]` or `["codex"]` in a copied manifest if an install turns out to need them. Entries whose own command is the CLI (copilot, grok, cursor, opencode, antigravity, devin, droid, omp) are already unavailable when it is missing.

**Facts from the real Grok CLI 1.0.77 (verified by the owner):** install with `npm install -g @xai-official/grok`; log in with `grok login`, or `grok login --device-auth` on a machine without a browser; the command line stays `grok agent {modelArgs} stdio` (its documentation recommends `--no-auto-update` for scripts; the placement is unverified, so it is mentioned in the entry's install text and not in `args`). The login probe is `grok models`, which exits 0 and prints "You are not authenticated." when logged out: the manifest's `auth.notLoggedInPattern` (a regular expression matched against the probe's stdout and stderr, which are otherwise discarded) turns that into "not logged in". An agent that offers only an interactive login (`grok.com`) is reported as "Grok is not logged in", with the login hint in a separate field. **Copilot** has no login probe: no non-interactive status command is documented in this repository, so its login state shows as unknown. **Codex** is available only when `codex` is on PATH (`requires`), with an install line (`npm install -g @openai/codex`); the adapter itself is fetched by `npx`, which cannot be checked offline.
