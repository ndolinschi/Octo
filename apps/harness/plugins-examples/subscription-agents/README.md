# subscription-agents

Claude Code, GitHub Copilot, Grok, Codex, Cursor, OpenCode, Antigravity, Devin, Factory Droid, Oh My Pi and Pi as ACP sub-agents. Each runs on the subscription its own CLI is logged in to; the harness never reads the CLIs' credential files.

This plugin is **built into the harness binary** (`embed.go` embeds `plugin.json`; there is no copy), so plain `harness serve` has it, no key needed:

```bash
go run ./cmd/harness serve
curl localhost:8790/v1/plugins    # builtin: true; available, logged_in (null without a probe), models, hint
```

To change it, copy this directory into `{data-dir}/plugins/` (or pass it with `--plugins-dir`): a plugin of the same name replaces the built-in one. `--no-builtin-plugins` / `HARNESS_NO_BUILTIN_PLUGINS=1` turns it off.

**Only the scripted fake agent has been run against this harness.** Copilot, Grok and Codex follow vendor docs; the other entries come from vendor docs, the ACP registry and secondary sources and are unverified (binary names, flags, probe exit codes, auth method ids).

The harness passes these processes only an allow-list of its environment (see "Child environment" in the harness `README.md`; `HARNESS_CHILD_ENV_ALLOW` adds names) and always hides its own `ANTHROPIC_*`, `OPENAI_*`, `XAI_*`, `GEMINI_*` ... variables so a subscription is not pushed onto per-token billing; an entry's `env` (for example `"XAI_API_KEY": "${XAI_API_KEY}"`) passes a variable on purpose. The commands, logins and env vars per agent are tabulated in the harness `README.md`, "Running on subscriptions" (with the scrub rules); `auth.methods` / `auth.skip` and the `{modelArgs}` placeholder are described in `../README.md`.

**Models (manifest fields).** `models` lists the models of an entry (with `modelLabels`, `modelsNote`); `roles` ({fast, balanced, deep}) says which model does each delegation tier; `modelsCommand` ({command, pattern, labelGroup}) runs a command that prints models. Only claude-code ships models: `opus`, `sonnet`, `haiku`, labelled "Opus", "Sonnet", "Haiku", with roles fast to haiku, balanced to sonnet, deep to opus. They are the aliases accepted by the Claude Code CLI's `--model` flag; unverified here (no primary statement of them exists in this repository; the owner uses them daily) and they are the CLI's own names, not dated model ids, so they do not go stale. Codex and Copilot list none, as nothing in this repository documents their names: for those the harness finds the models the agent advertises (it opens a throw-away session, no prompt, when the agent becomes ready or "Refresh models" is pressed) and the user can type a name per agent (`PUT /v1/providers/{id}/custom-models`), which is passed to the agent as typed. **Grok:** `modelsCommand` is `grok models` with a defensive pattern (one model id per line; a line counts when its first word has a hyphen or a digit after letters, so headings, "Available models:", "Models", version lines and "You are not authenticated." are ignored; a bullet `-`, `*` or `•` and trailing notes such as "(default)" are tolerated). **The real output format of `grok models` is unverified**: the pattern is a guess and easy to override: copy this directory into `{data-dir}/plugins/` and edit `agents[].modelsCommand.pattern` (group 1 is the id; `labelGroup` names a group for the display name). When the command prints nothing the pattern recognises, the harness falls back to asking the agent's session; either way the user can type a model.

**Login probes (advisory, never a lock).** Exit 0 always means logged in, whatever the probe prints. An agent is "not logged in" only when the probe exits non-zero and either its output matches `auth.notLoggedInPattern` or its status is in `auth.notLoggedInExit` (exit 1 for claude-code, codex, cursor and devin, the conventional status; unverified here; none for Grok). Any other outcome (another status, a timeout, a probe that cannot start, unexpected output) leaves the login "unchecked": the agent can still be chosen, the reason is in `harness doctor`. A request refused for a login offers "Use anyway" (`force_unverified`) and "Check again" (`POST /v1/providers/{id}/recheck`); see `docs/providers.md`.

**`flatRate` per entry** (used by automatic routing, `tier: auto`): `true` for claude-code, codex, copilot, cursor, antigravity and devin (the CLI's own subscription or plan is what is used; a key such as `CURSOR_API_KEY`, `WINDSURF_API_KEY` or `COPILOT_GITHUB_TOKEN` only authenticates that plan); `true` for grok too, **unless `XAI_API_KEY` is forwarded to it** (manifest `billingEnv`: variables that, when set in the environment the agent is started with, switch a flat-rate agent to per-token billing; decided at spawn, so a key from a spawn-time `env` counts; claude-code lists `ANTHROPIC_API_KEY` the same way, for a copied entry that forwards it); `false` for droid (token-metered plan with `FACTORY_API_KEY`), and opencode, omp and pi (they front arbitrary model providers whose billing is unknown). The choice is a judgement, not data: override it by copying the plugin (see above) and editing `flatRate`. **`strengths` per entry** (the owner's default, so a hard task can go to a subscription instead of always to the paid deep tier; copy the plugin and edit `strengths` to change it): `easy`, `medium`, `hard` for claude-code and codex; `easy`, `medium` for copilot and cursor; unset (never chosen by difficulty) for the rest.

**`requires` per entry** (commands that must be on PATH besides the entry's own command, else the agent is `available: false` with an `unavailable_reason` in `GET /v1/plugins`): only `pi` requires `pi` (its hint says "Needs pi on PATH" and its command is `npx`, which is there either way). Left out on purpose: claude-code and codex run through `npx` adapters and their hints say "log in with the CLI", not "install"; the adapters are said to bundle what they drive, and their login probe already reports a missing CLI as not logged in. Add `"requires": ["claude"]` or `["codex"]` in a copied manifest if an install turns out to need them. Entries whose own command is the CLI (copilot, grok, cursor, opencode, antigravity, devin, droid, omp) are already unavailable when it is missing.

**Facts from the real Grok CLI 1.0.77 (verified by the owner):** install with `npm install -g @xai-official/grok`; log in with `grok login`, or `grok login --device-auth` on a machine without a browser; the command line stays `grok agent {modelArgs} stdio` (its documentation recommends `--no-auto-update` for scripts; the placement is unverified, so it is mentioned in the entry's install text and not in `args`). The login probe is `grok models`, which exits 0 and prints "You are not authenticated." when logged out. Since exit 0 always wins (2026-11-12), that no longer turns into "not logged in" here: a logged-out Grok shows as "login unchecked", and the first turn fails with Grok's own message and the login hint. The manifest's `auth.notLoggedInPattern` still applies to a non-zero exit. An agent that offers only an interactive login (`grok.com`) is reported as "Grok is not logged in", with the login hint in a separate field. **Copilot** has no login probe: no non-interactive status command is documented in this repository, so its login state shows as unknown. **Codex** is available only when `codex` is on PATH (`requires`), with an install line (`npm install -g @openai/codex`); the adapter itself is fetched by `npx`, which cannot be checked offline.

**Manifest fields added 2026-11-12.** `verified` (bool, default false) and `verifiedNote`: only agents the owner has run with Octo are verified (claude-code, grok, copilot); the rest are listed `experimental: true`. `startHint`: one sentence added to the start-up failure message when the CLI rejects the launch arguments (antigravity: "Your agy version may predate ACP support. Update it (`agy update`) and check `agy acp --help`."). `unsupported`: a reason; the agent is listed with state `not_supported`, never probed, started, offered or routed to, and `acp:<id>` is refused with 422 `model_unavailable`; no built-in agent uses it today.

**Launch commands checked against primary sources (2026-11-12).** Google's Antigravity docs (https://antigravity.google/docs/cli/acp/) document `agy acp` (login `agy acp --login`); the owner's installed `agy` predates it. The ACP registry (https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json) matches ours for cursor (`cursor-agent acp`), opencode (`opencode acp`), devin (`devin acp`), pi (`npx -y pi-acp`), the codex and claude-code adapters and grok (`agent stdio`). Factory Droid is launched there as `droid exec --output-format acp-daemon` (our entry was `acp`; changed), with auto-update disabled through environment variables: see the registry for them, they are not copied here. Copilot: the registry uses `--acp` without `--stdio`; ours works on the owner's machine, so it stays and is marked verified. Oh My Pi (`omp acp`) is not in the registry: unconfirmed, experimental.
